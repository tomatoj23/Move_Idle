# 存档持久化设计 v1

- 票：#15｜日期：2026-09-03｜决议输入：issue #5（进度游标）、issue #7（数值层纯函数无 IO）、issue #9（last_seen/缺口/心跳）、issue #13（技能装配与解锁推导）、issue #14（背包/穿戴模型）、ADR-0001（Godot 4.7 / user://）、本票两轮拍板（13 问）
- 状态：设计定稿，待引擎实现

## 范围边界

- 本票管：本地存储选型（格式/布局/路径）、持久化状态集、写入时机、恢复流程、损坏与回档最小集、版本与迁移约定、重置进度。
- 本票不管：存档状态的**语义**（各归属票已定：#5 进度、#9 离线、#13 技能、#14 背包）、回归摘要面板演出（雾区 UI 票）、云存档与导出/导入（Out of scope / 雾区）。

## 1. 总纲

- **单档位**：MVP 单角色单职业，全游戏只有一份「这个玩家的进度」，无存档位选择。
- **格式 = JSON 纯文本**（`FileAccess` + `JSON.stringify`）：与内容管线同构、人类可读、加字段向后兼容。ConfigFile 表达不了嵌套实例数组；二进制不可读且防手改对单机放置无价值；Resource 违背 ADR-0001「Resource 仅承载表现资产」立场，且 .res 格式随引擎版本漂移。
- **路径 = `user://`**（Godot 标准用户目录，桌面/移动统一）。存档是运行时实例，绝不入 `content/`（站定决策）。
- 数值层纯函数无 IO（#7 硬约束），存档读写全部在引擎外壳层。

## 2. 存储布局：三文件

背包膨胀量级（#14 无限容量只进不出 + 挂机掉率）：一个月 1.7万~5万件实例 ≈ 3~12MB JSON——「每场遭遇全量重写」随档体积线性恶化（序列化卡顿 + 移动端写放大），故背包从主档剥离：

| 文件 | 内容 | 写模式 |
|---|---|---|
| `save.json` | 主档：除背包外全量状态（§3） | 原子全量重写（体积恒小） |
| `heartbeat.json` | `{last_seen, save_version}` | 原子重写，高频小写 |
| `inventory.jsonl` | 背包装备实例，**每件一行** | **append-only**，drop 即追加 |

- append-only 红利：#14 拍板背包**永不删除** → 零死行、**无需 compaction**；未来雾区「装备淘汰机制」毕业时再补重写合并。
- 单文件过大（数万行）时按件数切分多文件，属实现期优化，不是结构决策。
- 三文件同存于 `user://` 下一个专用子目录；备份轮转件（`.bak`，§7）同目录。

## 3. 持久化状态集

主档 `save.json`：

| 字段组 | 内容 | 来源票 |
|---|---|---|
| `save_version` | 存档版本整数，初值 1 | 本票 |
| `last_seen` | 最后在线时刻；与心跳文件取 max 后为缺口起点 | #9 §5 |
| `level`, `exp` | 角色等级与经验 | #5 §6 / #9 §3 |
| `idle_spot` | 挂机点 `{zone_id, tier}` | #5 §5 / #9 |
| `unlocked` | 解锁游标：`max_zone_order`（区域链推进游标）+ `zone_tiers: {zone_id: 最高已解锁阶}` | #5 §4 |
| `skill_slots` | 技能三槽装配：按槽位序的 skill id 数组 | #13 §2.4 |
| `equipped` | 三槽穿戴：`weapon/armor/trinket` 各存一个装备实例 uuid | #14 §6 |

背包 `inventory.jsonl` 每行一个实例：`{uuid, base_id, ilvl, rarity, mods: [{affix_id, tier, value}]}`——字段集由 #8 实例生成规则覆盖；实例身份 = 随机 uuid（Godot 内置生成），三槽按 uuid 引用，对未来雾区项（分解/出售/迁移）免疫下标漂移。

**不入档（推导或瞬态）**：
- `StatTable`：由等级 + 穿戴实例经 `aggregate` 纯函数重建（#7 §2）。
- 已解锁技能集：`unlock_level ≤ level` 即解锁（#13 §2.3 零新系统依赖），纯推导；未来技能书掉落（雾区）毕业时再显式化。
- 背包排序/筛选偏好：纯表现层（#14 §6）。
- 遭遇内状态（血量、tick 进度）与区域走图位置（遭遇下标）：瞬态；重启 = 从当前区域遭遇清单头开始，**挂机点是唯一锚**。
- 跨实例冗余（如按稀有度聚合统计）：可由背包全量推导。

## 4. 写入时机（事件驱动）

原则：**任何改变持久化状态的事件在其天然结算点落盘**。

- **主档 `save.json`**：① **离线补算入账后立即落盘**（防重复收益，§6）② 每场遭遇结束（经验/解锁变化都在遭遇边界产生；主档不含背包、体积恒小，无需节流）③ 玩家操作后（换装/换技能/选挂机点）④ 生命周期事件（退后台/退出/切应用）。
- **背包 `inventory.jsonl`**：drop 事件发生即追加一行（在线逐条、离线补算入账后一次性批量追加）；O(1) 写，无写放大。
- **心跳 `heartbeat.json`**：定期心跳（间隔归引擎实现，#9 §5/§8）+ 生命周期事件；心跳不触发主档全量。

一致性：三槽 uuid 引用指向的实例必然先于引用写入（append 先于穿戴操作），无交叉一致窗口。

## 5. 恢复流程（启动/回归）

1. 读 `save.json`：解析失败或关键字段缺失 → 回退 `save.bak`（§7）→ 再失败 → **新档开始**。
2. 版本检查（§8）。
3. 读 `inventory.jsonl` **逐行**解析：单行损坏**丢弃该行并计数告警**，不拒绝整个文件（append-only 语义天然支持行级自愈）。
4. 三槽 uuid 引用若在实例集合中找不到（坏行丢弃所致）：该槽降级为空并告警，不阻塞。
5. 读 `heartbeat.json`（坏/缺则用主档内 `last_seen`）；`last_seen = max(主档, 心跳)`。
6. 时钟回拨（`now < last_seen`）→ 收益归零并刷新（#9 §5 既定）。
7. 缺口 = `now − last_seen`，走 #9 离线补算 → **入账后立即全量落盘**。
8. 重建推导态：`aggregate` 生成 StatTable、按等级重建已解锁技能集。

## 6. 防重复收益（对 #9 的语义微修）

- #9 §7 原文「回归摘要面板一键领取统一入账」存在窗口：领取后、落盘前崩溃 → 重启重新补算 → **重复收益**。
- **微修为：补算完成即入账并立即落盘**（`last_seen` 随之刷新），摘要面板降级为**纯展示**（「领取」按钮只是确认 UI，演出不变）。补算本身幂等（未落盘即重来），窗口归零。

## 7. 损坏与回档最小集

- **原子写**：写 `<file>.tmp` → `JSON.parse` 自校验 → rename 原子替换；替换前当前文件轮转为 `<file>.bak`（保留 1 份）。适用于 `save.json` 与 `heartbeat.json`；`inventory.jsonl` 为追加写，靠行级丢弃自愈（§5.3），不做原子化。
- **恢复顺序**：`save.json → save.bak → 新档`。单机放置无竞技价值，回档损失可接受；强杀进程场景 `.bak` 覆盖绝大多数窗口。
- **不做**：checksum、加密、防篡改（手改存档是玩家自由）；滚动多份备份。

## 8. 版本与迁移

- 主档与心跳均带 `save_version`，检查以主档为准。
- `version > 引擎支持版本` → **拒载并提示**（防旧程序读新档崩溃）。
- `version < 支持版本` → MVP 不实现迁移器，但立两条**前向兼容约定**：未知字段忽略、缺字段补默认值；未来升版时引擎侧以**迁移函数注册表**补齐（一个版本一个函数）。

## 9. 重置进度

- 设置面板提供「重置进度」：二次确认后删除三文件及其 `.bak`，回到新档。单档位模型的必要兜底，不算入 UI 票范围。
