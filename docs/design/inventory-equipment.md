# 背包与装备管理设计 v1

- 票：#14｜日期：2026-09-03｜决议输入：issue #9（离线结算，背包 v1 接口）、issue #4（内容 schema，槽位与实例模型）、issue #7（战斗结算，属性聚合）、issue #12（遭遇模型）、issue #13（build 载体）、本票一轮拍板（Q1~Q5 全按推荐）
- 状态：设计定稿，待引擎实现

## 范围边界

- 本票管：穿戴/卸下/替换的操作模型、换装生效时机、背包容量与整理、换装界面入口、多余装备出路。
- 本票不管：背包/穿戴状态进存档的格式（存档持久化票）、掉落 roll 语义（#8）、技能槽装配（#13）、插槽符文/威能加工等装备玩法扩展（雾区）。

## 1. 穿戴模型：三槽一对一

- 穿戴位 = item-base schema 的槽位枚举：`weapon / armor / trinket` **各 1 件**，角色同时最多 3 件。
- `category`（sword、helm…）是槽位下的细类，不影响槽位数：同槽内任意 category 可互换（长剑换短斧仍是 weapon 槽）。
- **替换 = 同槽一对一**：新件穿上、旧件无损回背包，一次操作完成；不存在「卸下腾位」的中间态。
- **卸下** = 穿戴位实例移回背包（背包无上限，永远放得下）。
- 穿戴集合是聚合输入：#7 §2 的属性来源 = 玩家初始值 + **已装备实例**词缀值，换穿即改变该集合。

## 2. 换装时机与生效：任意时刻即时生效

- **任意时刻可换**：自动战斗进行中不锁换装，无「战斗锁死」或「仅遭遇间」的窗口。
- **生效机制**：换装触发 `aggregate` 重聚合——与升级共用同一触发器（#9 §3「升级即时抬基准、即时重聚合」），下一 tick 起按新 StatTable 结算（#7 tick 制天然支持）。
- **当前遭遇不中断**：进行中的遭遇继续打，剩余部分按新属性结算；怪血量与战斗进度不变。
- **离线对齐**：「离线结算同样按当前 build 生效」= 按离线开始时刻的已装备集合，逐场固定（离线中无换装事件）；在线换装不影响离线同构性——离线模拟只消费开始时刻的穿戴快照。
- 换装不动技能槽：技能装配（#13，三主动槽）是独立操作；build = 装备 × 技能，两个面板各自承载。

## 3. 背包模型：无上限、只进不出

- 数据模型 = **装备实例数组**（#9 §6 既定接口的完整化）：无上限、永不自动清理、永不自动分解；掉落是唯一入口。
- **排序/筛选**（按稀有度/槽位/词缀数等）是**纯表现层**视图操作：不进数据模型、不进存档、离线不感知。
- 相同属性的装备不去重、不合并：一实例一行，堆叠数不受限。
- 24h 离线补算的掉落全量入背包（#9 §1「掉落实例真实可领」的承诺依赖背包永不截断收益）。
- 本票无新增引擎常量。

## 4. 界面入口：单一背包面板

- **单一背包面板**承载换装：左侧角色三槽（穿戴中）、右侧全量装备列表，点选穿/脱/替换。
- 面板内**只读展示当前聚合属性**（消费 StatTable，#7 §2；与 #10 编辑器的「装备试算面板」同函数异端），换装后即时刷新。
- **装备详情 v1 只显示自身信息**：稀有度、基底（名称/槽位/材质）、词缀明细；**不做**与穿戴中装备的 diff 对比提示（表现层增强，雾区）。
- 背包面板与挂机点选择面板**相互独立**、互不嵌套（挂机点 = {区域, 阶}，#5 契约）。
- **配装方案保存（build preset）不做**：单角色 3 件手换成本极低，方案管理是真实痛点出现后的表现层功能（雾区）。

## 5. 多余装备的出路：MVP 无淘汰机制

- 分解/出售/销毁**均不进 MVP**：装备只进不出，背包靠无上限承受堆积。
- 理由：无容量压力下淘汰机制不解决任何真实玩家问题；出售需连坐定义货币系统与货币 sink、分解需连坐定义材料系统与用途——连锁复杂度远超本票。
- 既有雾区对本票的依赖：插槽+符文（#13 C4）、威能迁移与装备加工（#13 C5）建在装备管理之上，仍属 post-MVP；本票再把「淘汰机制」并入雾区。

## 6. 对其他票的输入

- **存档持久化（前沿票）**：本票新增需持久化状态 = 背包实例数组（有序，入包序）+ 三槽穿戴引用；排序偏好不持久化（纯表现层）。
- **雾区新增**：装备淘汰机制（分解/出售，需先定货币或材料系统）；装备 diff 对比提示；配装方案保存。
- **编辑器（#10 已关）**：游戏内背包面板的聚合属性展示与编辑器「装备试算面板」共用 `aggregate` 纯函数，两端展示语义一致。
