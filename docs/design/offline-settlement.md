## 范围边界

- 本票管：离线收益的产生模型（怎么算出来）、缺口与上限、防滥用、回归领取的表现、MVP 最小拾取模型。
- 本票不管：背包穿脱/整理/容量细则（毕业新票）、掉落 roll 语义（#8）、进度解锁写入（#5）、摘要面板的具体演出（雾区 UI 票）。

## 1. 总纲：模拟补算，不是速率折算

- 离线收益**不做**「在线速率 × 时长」的期望折算，而是**回归时用数值层真跑一遍**：与在线完全同构（同一 `run_encounter` / 掉落 roll / 事件流），掉落的装备实例真实可领，不存在「期望 3.7 件怎么发」的问题。
- 结算时机：回归启动时一次性补算。O(场次数)：24h 上限下单场按 10~30s 估约 3000~9000 场，GDScript 纯函数秒级完成。
- 执行端：引擎（Godot）侧。数值层无 IO/引擎 API 依赖（#7 硬约束），天然可离线驱动；#7 提及的「Node 离线」已被 #6 引擎选型取代，同构原则不变。

## 2. 模拟时钟驱动

- **不预估场次数**：逐场 `run_encounter`，把每场 `duration_ticks` 累计为模拟时钟，**覆盖缺口时长即停**。快场自动多打、慢场自动少打，无需测定单场时长、无估计误差。
- 遭遇间无时间间隙（回满是规则不是耗时，#7 既定），模拟总时长 = 各场 duration 之和。
- 最后不足一场的尾巴**整场保留**（不截半场）：实际模拟时长最多超出缺口一场。
- 每场产出照常：经验、drop 事件（真实装备实例，#8 同规则）全量入账。

## 3. 离线期间的角色成长

- **逐场生效**：每场击杀经验照常入账，升级即时抬基准、即时重聚合（`aggregate` 纯函数逐场调用，成本可忽略）。与在线「逐场得经验、当场升级」同构，长离线不亏后期收益。
- 掉落 ilvl 按实际产出地点的有效等级（区域 level + 阶 × 步长，#5 同规则）。

## 4. 打不过怎么办：复用回退逻辑

- 玩家可能自选一个当前 build 打不过的挂机点（换 build 变弱后下线、手动选了过高阶）。离线**复用在线推进状态机**：失败 → 退当前区域起点重刷 → 再败退上一区域起点（#5 §4），只是**不写任何解锁**。
- 回退是后退不是推进：不违反「离线不推进进度」的本意（不解锁新内容）。
- 产出地点允许漂移（ilvl 随之下降），与在线行为同构，**永不白挂**。

## 5. 缺口时长与防滥用

- **缺口时长** = `now − last_seen`。
- `last_seen` 写入：生命周期事件（退后台/退出）+ 定期心跳。心跳保证在线切后台（进程未被杀）时缺口 ≈ 0，不会与在线收益重复结算；进程被强杀最多损失一个心跳间隔。
- **最大离线时长 = 24h**（引擎常量）：缺口超出部分不补。
- **时钟回拨**（`now < last_seen`）：本次收益归零，`last_seen` 刷新为 `now`。
- **中断成因统一**：进程被杀、断电、切后台被冻结一律按缺口补算——不判定成因、不区分「真假离线」，全游戏只有一种结算路径。

## 6. MVP 最小拾取模型（本票钉死）

- **drop 即自动入背包**：drop 事件发生即装备实例进入背包，无拾取动作、无地面物品；在线/离线同规则。
- 背包 v1 = **无限容量纯列表**（装备实例数组）；穿脱/替换/整理/容量/分解归毕业新票。
- 至此核心循环「掉落 → 替换 build」在 MVP 内闭环。

## 7. 回归领取表现

> ⚠️ 入账时机已被 `save-persistence.md` §6 微修：补算完成即入账并立即落盘（防重复收益），摘要面板降级为纯展示，「一键领取」只是确认 UI。

- 回归启动即弹**离线结算摘要**面板：缺口时长、击杀数、总经验与升级明细、掉落统计。
- 掉落按稀有度聚合展示；稀有/传奇列明细，传奇置顶高光（复用 #8 演出阶梯）。
- **一键领取**统一入账；v1 为模态面板（领完进游戏）。

## 8. 引擎常量表

- `max_offline_seconds = 86400`（最大离线补算时长，24h）
- `last_seen` 心跳间隔（实现细节归引擎）
- 经验/升级/掉率常量沿用 #5/#8，本票无新增数值。
