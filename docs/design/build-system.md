## 范围边界

- 本票管：build 差异的承载载体——技能侧骨架（内容模型/槽位/获取/施放）+ 装备侧特性包（#17 候选 C1~C6 拍板）+ build 空间验收线。
- 本票不管：套装内容模型细节（毕业「设计：套装内容模型与试点方案」票）、背包与装备穿脱（#14）、存档（#15）、技能 roster 谱系扩充（内容管线期）。

## 1. 根决策（含修订过程）

**build 差异 = 技能 × 装备共同承载。**

过程记录：初轮曾拍板「纯装备驱动 + 基础技能常量保留（非构筑对象）」；用户在 #17 调研结论上修订根决策——技能入局，build 空间由技能与装备两轴组成，「基础技能常量保留」随之失效重谈（升级为初始技能内容）。

## 2. 技能侧设计

### 2.1 技能内容模型

- 新内容类型「技能」（第 9 种），schema 落 `schema/skill.schema.json`，示例落 `content/skills/`。
- 字段：`id` / `name` / `flavor` / `profession`（可选职业归属，多职业扩展位）/ `multiplier`（技能倍率）/ `cooldown_ticks` / `damage_type`（复用 common 六元素封闭枚举）/ `unlock_level`。
- 技能是**配方**（内容数据），玩家侧装配结果（槽位组合）是运行时状态，不回写 `content/`——与装备配方模型同理。
- 首两个示例：`skill_heavy_strike` 重斩（multiplier 2.0 / 50 tick / 物理 / 解锁 1，承接 #7 基础技能常量数值）、`skill_fire_bolt` 火弹（2.2 / 60 tick / 火 / 解锁 5）。

### 2.2 槽位与自动施放

- **三主动技能槽**，无被动技能——被动型效果已由 stat_amp 词缀承载，再做被动功能重叠。
- 自动施放 = **冷却好即放、按槽位序取技能**；不做条件优先级逻辑（放置玩法约束，深究留平衡期）。
- 初始装配：重斩默认占据一槽；其余槽随解锁填充，玩家在界面自由调配。

### 2.3 获取

- **等级解锁**：技能带 `unlock_level`，角色达到即自动解锁。零新系统依赖（升级已由 #5 钉死），解锁本身即进度感。
- 技能书掉落、商店购买均不做（雾区/排除，见 §6）。

### 2.4 与 #7 战斗结算模型的修订

- 技能倍率因子来源：由「引擎常量」修订为「当前施放技能的 `multiplier`」；普攻倍率恒 1.0 不变。
- `run_encounter` 的 `skill_config` 修订为**装配技能数组**（按槽位序），由内容管线供给、存档持久化。
- 技能命中照常发 `on_attack` 事件（`skill` 字段 = 当前技能 id）——词缀 `proc_on_hit` 照常 roll、暴击因子照常 roll；**不引入 proc 系数**（D3 式按技能降 proc 的平衡手段留平衡期）。
- 事件模型零变更；`explode_fire` 语义沿 #12 结论。

### 2.5 边界

- MVP 技能**单目标**（与普攻同），不做 AOE——#12 遭遇模型零改动。
- 不做技能升级/技能强化（技能无档位；「技能进阶」类深度留 post-MVP）。
- 不做技能与词缀的联动原语（如「某技能获得 proc」——传奇词缀效果作用于全局攻击，未来若需技能定向效果 = 原语扩展，走 schema 升版）。

## 3. 装备侧特性包（#17 候选拍板）

| 候选 | 拍板 | 说明 |
|---|---|---|
| C1 传奇词缀扩容 | ✅ 进 MVP | roster 10 → 20+，四原语 × 多元素 × 多槽位；纯内容供给，机制零改动 |
| C2 固有属性供给扩容 | ✅ 进 MVP | `implicit_mods` 已在 schema v1（术语：固有属性），首批基底配齐差异化数值；聚合逻辑（来源求和）不变 |
| C3 套装试点 | ✅ 试点进 MVP | 1~2 套小规模（2/3 件套小效果），**不做 D3 式 6 件套 build 地基**；细节毕业独立票 |
| C4 插槽 + 符文/宝石 | ⛔ 雾区 | 与传奇词缀功能重叠（外挂效果位）；插槽管理依赖 #14 |
| C5 威能迁移 / 装备加工 | ⛔ 雾区 | 装备管理玩法，与放置定位弱兼容；#14/#15 之后视需求 |
| C6 技能等级词缀 | ⛔ 排除 | 技能入局后由技能本体承载，「+技能等级」类词缀不再有表达对象 |

固有属性边界（Q5=A）：固有属性**保持纯 stat**；玩法特效（四原语）唯一出处 = 传奇词缀。「基底的身份是数值，掉落的惊喜是词缀」。

## 4. 冒险模式与职业

- **MVP 单人**，无组队——组队维持地图 Out of scope（多人/联机条目）。
- **佣兵进雾区**：玩家侧第二 combatant，牵动 #12 遭遇模型（目标选择）、佣兵 build 承载、死亡/复活、离线同构——遭遇模型稳定后毕业。
- **单职业身份**：MVP 一个职业，技能池绑定该职业；`profession` 字段留多职业扩展位。「多职业多角色」Out of scope 条目语义不变（不做职业选择）。职业暂不立术语（无独立机制，仅归属标签）。

## 5. 验收线（build 空间成立标准）

- **装备侧四原型可成型**（Q6=A）：
  1. 冰霜全转流（寒霜之魂 convert 100% + 冰系词缀）
  2. 烈焰半转流（烈焰之心 convert 50% + 火伤词缀）
  3. proc 触发流（腐蚀之触/雷霆贯击/霜咬 + 狂暴之心/亡者低语攻速放大）
  4. 暴击玻璃炮（泰坦之力 + crit 词缀 + 血之盛宴兜底）
- **技能侧**：三槽装配组合产生可感知战斗差异（倍率/伤害类型/节奏）；技能 roster 谱系（数量、元素覆盖、倍率分布）随内容管线期定。
- 原型线 K=4 为 MVP 规格（/to-spec）的验收标准；roster 扩充方向以原型可成型为准。

## 6. v1 排除与雾区

- 雾区新增：佣兵系统、插槽 + 符文/宝石、威能迁移与装备加工/洗练、技能书掉落、技能 roster 谱系。
- 明确排除：组队冒险（Out of scope）、多职业选择（Out of scope 语义不变）、技能 AOE、技能进阶、被动技能槽。
