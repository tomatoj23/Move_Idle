# 编辑器资产产线枢纽（MVP 范围与接口）

票 #16 决议文档 · 2026-09-03

## 背景与定位

编辑器从「内容数据工具」（#10 决议：浏览 / JSON 手编 / 校验面板 / 引用跳转 / watch）扩为「资产产线枢纽」，新增资产管理面。不推翻 #10 决议：内容生成仍由 agent 产线承担、编辑器零 LLM 集成、不内置 git。输入契约 = 资产规格（`art-asset-spec.md`）：§2 许可政策、§5 命名与帧结构、§6 网格基线、§7 图标产线；校验器资产存在性检查为其镜像数据源。

三职能 MVP 范围：**全进**——互相咬合（导入产 registry、缺口识别消费映射、任务包连 agent 产线），砍任何一项断链。

## 职能 1：缺口识别 → 制作需求打包

- 口径 = **纯资产缺口**（命名映射断链）：内容对象存在但映射资产缺失——`content/monsters/<id>.json` 无 `game/assets/monsters/<id>/`、装备基底 id 无 `game/assets/icons/<base_id>.png`、hero 固定目录缺失（hero 无内容对象，按固定路径特判）。
- 数据源 = 校验器资产存在性检查的镜像视角：同一索引，断链即「待制作」；UI 呈现断链清单，勾选即生成任务包。
- 内容量目标缺口（「词缀池应 20 条」类）不进 v1，记雾区。

## 职能 2：资产库管理

- 清单载体 = 集中单文件 `game/assets/registry.json`；`manifest.json` 保持不动——它是引擎消费的帧结构契约，registry 是产线消费的来源与状态台账（关注点分离）。
- 条目字段：`asset_id`、类型（monster / hero / icon）、目录路径、来源 URL、许可（CC0 / CC-BY / AI 生成）、状态（占位 / 正式，导入默认正式）、入库日期、许可快照档指针（`docs/research/licenses/` 档名）。
- 与内容数据的引用闭合**不归** registry（既有命名映射存在性检查的职责）；校验器扩展 registry ↔ 磁盘双向断链检查。
- 预览粒度 = 静态图：spritesheet PNG 缩略 + 图标 PNG 直看（Node 本地服务加静态文件端点）；动画播放器记雾区。

## 职能 3：外来资产导入

- 流水线 = 导入向导（来源 + 许可登记 → 校验 → 预览落位路径 → 确认写入）→ 落位 `game/assets/<type>/<id>/` → registry 记账。
- staging 收件箱不进 MVP（#10 保险条款「git diff review 不够用时再开」未触发）：写错 git 兜底、registry 手改。
- 对象类型范围：monsters 动画包 / hero / icons 三类；UI 图集后置记雾区。
- AI 生成图标记账口径：向导按来源分支——AI 生成物跳过 §2 许可检查项，registry 来源记「AI 生成（<模型名>）」、状态正式；许可快照与平台披露义务仍归资产规格 §7 管辖，§2 条款不改。
- 外来第三方资产：按 §2 过许可检查（CC0 / CC-BY 底线），许可快照入 `docs/research/licenses/` 对应档（换包/升版重抓惯例不变）。

## 任务包（制作需求）契约

- 格式 = 单一 Markdown（正文叙述 + 内嵌 JSON 代码块承载结构化清单），落 `docs/tasks/<date>-<slug>.md`。不放 `content/`：那里 id 即文件名、每对象一文件，校验器目录扫描也要避开。
- 骨架（编辑器产出侧；skill 侧消费约定归用户自制 content-authoring skill）：

```markdown
# 任务包：<标题>
- target: asset | content   <!-- v1 仅 asset，字段预留 -->
- 目标清单：<缺口列表——monster id / base id / 目录或文件路径>
- 约束：<数量；§5 命名与帧结构；§6 网格基线；风格锚点 → 资产规格 §1>
- 参考：<schema 摘要指针；属性注册表指针；同类已存在 id 清单>
- 验收：pnpm validate 全绿 + 落位路径符合 §5 映射
```

- 通道：**文件为主**（agent 有仓库访问，#10 协议 = 文件系统的主通道）+ **剪贴板兜底**（无仓库访问的纯聊天 agent：同一任务包一键复制回贴）。一个格式两种通道，序列化只实现一次。#10 雾区「剪贴板任务包通道」就此落位。
- 生命周期：一次性用完即删（手动，编辑器不内置 git），不归档。

## 校验器职责边界

- **同一 TS 校验器包内新增资产检查模块**（唯一实现、双消费者：CLI + 编辑器 import），不建独立检查器（`CONTEXT.md`「校验器」= 唯一工具）：
  - 资产存在性检查（既有职责，§5 命名映射断链）；
  - registry ↔ 磁盘双向断链检查（新增）；
  - 导入校验（许可登记必填、§5 命名与 manifest 字段、§6 网格基线、落位路径断言）。
- 引擎侧照旧只做轻量断言，不重复实现。

## 雾区新增（毕业记录）

- 资产库动画播放器（读 manifest 逐帧播放）——表现层工具，静态图预览不够用再开。
- UI 图集导入——UI 资产真实需求出现再开，向导扩一类即可。
- 内容量目标缺口识别 + 任务包 content 类目标——内容填充期需要规划工具再开；格式已预留 `target` 字段。
- staging 收件箱（资产侧与内容侧）——维持 #10 原条件（git diff review 不够用时再开）。

## 术语

`CONTEXT.md` 新增：**资产库**、**任务包**（架构分层组）。
