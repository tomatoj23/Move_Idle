# 套装内容模型与试点方案设计 v1

- 票：#18｜日期：2026-09-03｜决议输入：#13（Build 多样性载体，C3 毕业出口）、#17（装备特性调研 §3 套装评估）、#8（掉落与稀有度）、#14（背包与装备管理）、#7（战斗结算模型）
- 状态：设计定稿；set schema 与两套试点示例内容已随本票落盘

## 范围边界

- 本票管：套装内容模型（套装对象 schema、成员声明、效果阶梯）、套装件与掉落链的接入、试点范围与强度锚。
- 本票不管：稀有度档位结构本身（#8 既定，扩档契约见 §6）、背包装备穿脱（#14）、套装件 UI 展示细节（归编辑器/表现层）。

## 1. 根决策：套装件 = 专属基底，非第五档稀有度

套装件是「专属装备基底」，照常走 #8 三层判定链进掉落表；稀有度四档机制零改动。

- 不做 D3 式第五稀有度档：权重表、稀有度枚举、drop 事件契约、实例生成规则全线不动。
- 收集感由专属基底的低出现率（掉落表内容供给）提供，不靠稀有度特权；D4 现状同构（套装归属的传奇装备，而非独立稀有度层）。
- 成员资格声明长在套装对象上（单一真相）：套装持有 `members`（成员基底 id 列表），基底侧零改动（`item-base.schema.json` 不加字段）；与既有 `family` 字段的「由基底声明」惯例不同——套装需要独立对象承载效果阶梯，成员收在集合对象里内聚。
- 校验器检查：`members` 引用的基底 id 存在；各成员 `slot` 互不重复（三槽一对一 → 一槽一成员，成员数 ≤ 3）；`tiers[].pieces` ≤ 成员数且按升序。

## 2. 内容模型（set.schema.json）

- 新内容类型，schema 落 `schema/set.schema.json`（`urn:move-idle:schema:set:v1`，新增文件 = additive，不触发全库升版；skill 先例）。
- 字段：`id` / `name` / `flavor` / `members`（2~3 个成员基底 id）/ `tiers`（效果阶梯）。
- **效果阶梯复用传奇四原语**：`tiers: [{pieces, effects}]`，effects 直接 `$ref` common v1 的 `effect_primitive`（stat_amp / proc_on_hit / proc_on_kill / convert_damage）。原语封闭集不扩 → 不触发 README 规则 7，无需 ADR。
- 引擎侧语义 = 「穿着件数达标才聚合的原语求值」：proc/convert 求值器与传奇词缀共用同一套实现，离线同构自动成立。
- 套装效果数值**固定不随 ilvl roll**（同传奇词缀 #8 约定）；阶梯阈值 `pieces` 最低 2（1 件档无收集语义）。
- 「穿着 N 件」只数装备槽中的成员件，背包里的不算；每套独立计数，多套可并行激活各自达标档。
- 套装归属是推导态不入档（#15 原则）：实例带 base_id，运行时由 base_id → 套装反查计数，存档零改动。

## 3. 套装件与掉落链

- **稀有度下限**：套装件照常 roll 四档，结果低于稀有档（rare）则 clamp 到稀有（引擎一行逻辑）。套装件身份 = 「3~4 条 stat 词缀 + 套装阶梯特效」，不与传奇词缀强度叠加。
- 上限不特判：roll 到传奇档的套装件 = 传奇词缀 + 套装阶梯（极稀有惊喜：传奇权重 1/100 × 套装件出现率），试点期观察点，不做特例压制。
- **显示名恒 = 基底 `name`**（如「熔核巨剑」），不走 #8 §4 前后缀组合命名——专属名即身份。
- **渠道 = 掉落表内容供给**：成员基底**不带 `family` 字段**，天然不进家族 roll 池，只能被掉落表 `type=base` 显式指定——套装件出现率完全由内容显式控制。试点挂载规则：首领掉落表定向配（目标感）+ 普通怪掉落表小权重（惊喜），与传奇渠道同风格。首领「必掉」是掉落判定层（掉不掉），必掉 ≠ 必掉套装件。
- 重复件照常入背包（#14 只进不出），无淘汰机制。

## 4. 引擎接入点

- 属性聚合链第四来源：基底固有属性 + 词缀 + …… + 套装阶梯（件数达标才并入）。`stat_amp` 类进 StatTable 聚合；`proc_on_hit` / `proc_on_kill` / `convert_damage` 类进结算钩子，与传奇词缀同一求值器。
- 聚合触发复用 #14 换装重聚合（换装改变件数 → 即时重聚合，当前遭遇不中断）。
- 离线同构：离线按开始时刻穿戴快照逐场固定（#15 已定），套装件数随快照，阶梯效果照常生效，零额外机制。

## 5. 试点范围（钉死）

- **2 套 × 3 件套**（weapon/armor/trinket 各一），阶梯 = 2 件档 + 3 件档。一套攻击向（stat_amp/convert 系）、一套生存/proc 向，覆盖两种效果组合方向。
- **强度锚**（供内容生成与平衡参考，引擎不消费，风格同 power_rating）：
  - 2 件档 ≈ 一条 stat 词缀高端档量级（属性放大 ×1.10~1.15，或 proc p≈5%）；
  - 3 件档 ≈ 一条传奇词缀量级（stat_amp ×1.10~1.15，或 proc p≈15%~25%，或 convert ≤25%）；
  - 总约束：一套穿满的总收益 ≤ 两条传奇词缀。
- **首批试点内容（已落盘）**：

| 套装 | id | 成员（weapon/armor/trinket） | 2 件档 | 3 件档 |
|---|---|---|---|---|
| 熔核之誓 | set_magma_core | base_magma_greatsword / base_magma_plate / base_magma_signet | stat_amp：攻击速度 ×1.10 | convert_damage：物理→火焰 25% |
| 回响圣所 | set_echo_sanctum | base_echo_mace / base_echo_robe / base_echo_amulet | stat_amp：生命上限 ×1.12 | proc_on_kill：20% 概率回复 4% 最大生命 |

- 成员基底自带差异化固有属性（C2 供给），材质对齐首批基底量级（attack_power 10~14）。

## 7. v1 排除

- 套装转换/套装件重铸（D3 卡奈套装转换）→ 不做，属装备加工玩法（#17 C5 雾区）。
- 套装专属词缀池（成员件限定词缀）→ 不做，词缀池过滤机制（#8）已够用。
- 集齐套装的 UI 演出/成就 → 表现层雾区。
- 超过 3 件的套装（四件以上阶梯）→ 三槽硬约束下无意义，模型上由 members 上限 3 封死；未来若开更多装备槽随 #14 演进。
