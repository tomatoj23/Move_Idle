# 0001: 技术栈选型 Godot 4.7.x（GDScript）

Move_Idle 是 2D 横版放置 ARPG，最终产出**桌面端 + 移动端独立 app**（一键运行），内容与引擎完全解耦（`content/` 纯 JSON + 本地 Web 内容编辑器 + LLM 批量生成管线）。决策票 [#6](https://github.com/tomatoj23/Move_Idle/issues/6) 于 2026-09-02 拍板如下。

## 决定

- **引擎 = Godot 4.7.x，脚本语言 GDScript**（C# 移动端为实验性，不采用）。
- **内容数据消费 = 纯 JSON 直载**：启动时 `FileAccess` 读取 + 运行时校验；数值内容**永不转换为 `.tres`、不进 Resource 体系**；Resource 仅承载表现资产（场景/纹理/图集）。`content/` JSON 是唯一事实源，编辑器与 LLM 管线只认它。
- **表现层特效路线 = 程序化为主**：GPUParticles2D + 自定义 shader + Tween（hit stop、震屏、闪白、数字弹跳）；**特效 = 配方**（视觉模板 + 参数，运行时生成实例，可由 LLM 生成与批量扩展），与内容系统的配方模型同构；角色/怪物动作用现成序列帧资产包（以「命名约定 + 帧结构约定」为替换接口）；序列帧特效仅作点缀，不是主力。

## 被否选项

- **Web/TS + Tauri 2 全端**：单语言零异构税（数值层/编辑器/离线结算同构）是最大优势，但壳工程首配重、WebView 性能上限低；用户约束「尽可能酷炫的表现 + 不想为美术资源费心思」下，Godot 原生粒子/着色器工具链价值更高。落选。
- **Godot + C#**：桌面可行，移动端为实验性支持。落选（故选 GDScript）。
- **Godot + 导入期转 .tres**：内容被引擎绑定，违背「内容与引擎完全解耦」站定决策。落选。

## 后果

- 接受**双语言复利税**：数值层（GDScript）与内容编辑器（Web/TS）异构，JSON Schema 校验需两套实现保持同步（或引入代码生成，待编辑器管线票权衡）。
- Godot Web 导出的粒子兼容性存在历史问题（godotengine/godot#96030，archived 关闭、未确证根治）——Web 非目标发行形态，风险接受；移动端注意 compatibility 渲染器下的粒子可见性排查。
- iOS「一键运行」受苹果分发规则约束（与引擎无关）：开发者账号 + TestFlight，或 7 天过期的个人证书；Android 侧可直接分发 APK。
