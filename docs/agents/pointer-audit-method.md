# 指针 / 机制改动验证方法（带外）

> **本文件是审计工具，不是开发流程文档。** 按既有约定（带外文档不进 `AGENTS.md`），它不在指针链上，唯一入口是 `docs/agents/audit-runbooks.md` Runbook B。
> **读到本文件 = 知情。** 若被测会话的时间线里出现本文件、`.codebuddy/memory/2026-09-06.md` 或预登记表，则「是否主动读某页」类判据（主要是 #6、#11、#14）一律作废，只保留**顺序 / 产物 / 漏项**判据。

## 0. 这套方法在防什么

文档指针、skill、CI 钩子都是「为了让会话少踩坑」而写的，但它们从不自己证明自己有效。常见三种自欺：

1. **声称 ≠ 实做**：会话说「我跑了 X」，时间线里没有对应 CALL。
2. **顺序没验**：规范是落码之后才读的——读了也没用。
3. **判据事后改**：拿到结果再改判据，等于自造绿。

本方法用**预登记 + 四档判分 + 反向判据**防这三件事。

## 1. 三层框架（判据按层归类）

| 层 | 是什么 | 期望 | 失效含义 |
|---|---|---|---|
| **机器层** | CI / pre-commit 强制执行的检查 | **100% 触发**（强制项） | 最严重：没装机或被绕过 |
| **skill 层** | 由 description 触发、按需注入 | 相关时机 ≥1 次**自动**触发 | description 写得不好，或没被索引到 |
| **指针层** | 文档里的「读这个」 | **读先于落码** | 指针失灵 → 按 `process-audit.md` 归类加固 |

**权重排序**：顺序、产物、漏项 **>** 「有没有读某页」。后者最容易表演，前者很难。

## 2. 工具：先降维，再判读

导出件动辄 1MB+，直接读会爆上下文。

    powershell -File tools/session-audit.ps1 -InputFile <导出.json>
    powershell -File tools/session-audit.ps1 -InputFile <导出.json> -TimelineOnly

输出六段：结构勘察 / 消息清单 / 工具调用时间线 / 三层锚点计数 / 关键词上下文 / 对话正文。

- **先看「结构勘察」**：节点类型与预期不符就先修脚本映射，不硬套。
- **脚本只降维、不判分**：判据在 §4 的预登记表里，脚本里一条都没有。脚本能改判据 = 能自造绿。
- 脚本文件**必须带 BOM**，否则 PowerShell 5.1 按 GBK 读中文，输出全乱码。
- 导出件与 digest 都放 `.codebuddy/audit/`（被 gitignore，不入仓库，也避免被测会话看见痕迹）。

## 3. 执行步骤（拿到 JSON 后）

1. **勘察结构**（脚本输出第 1 段）。
2. **查污染**：按开头规则判断是否作废「是否主动读某页」类判据。
3. **跑脚本降维**。
4. **逐行只填档**：🟢 / 🟡 / 🔴 / ⚪。不新增、不删除、不改写判据行。
5. **回流**：🟡 / 🔴 按 `process-audit.md`「失守归类 → 反哺映射」表归类反哺。这是**开发内动作，不启动带外 runbook**。

## 4. 判据表在哪

**刻意不放在仓库里**——放仓库 = 被测会话能提前看到答案。

位置：`.codebuddy/memory/pointer-audit-2026-09-06.md`（15 行，四档判分，含「判绿陷阱」列）。

修订规则：**允许在拿到下一份 JSON 之前修订**；拿到之后只允许填档。修订须注明日期与原因。

## 5. 判分与纪律

- 四档：🟢 触发且正确 / 🟡 分支发生但没生效（**最该抓的一档**）/ 🔴 触发了但行为错 / ⚪ 分支未发生，本次不可判定。
- **⚪ 禁止记成通过。** 也不得为了凑覆盖面去诱导会话做某件事——那是探针，属带外 Runbook A。
- **n=1 不调参**：单票结果只记录；同一项**连续两票**都 🟡/🔴 才动机制（区分「机制没用」与「这次恰好没碰上」）。
- 验证不得扭曲被测任务本身：机制若碍事（如检查误报拦了提交），照实记录为数据点，不为「证明机制有效」而表演。

## 6. 背景

本方法成型于 2026-09-06 的执法体系审计：四条验收线中「已有教训能否防重踩」判红，根因是**教训只留在被 gitignore 的记忆里、没变成可查判据**——回流进仓库的几条当天就抓到了真问题，没回流的四条全部跨日复发。
