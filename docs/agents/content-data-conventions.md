# 内容数据 agent 操作约定（content/）

状态：生效（2026-09-06）｜范围：`content/` 下 JSON（zone / base / skill / monster / legendary affix / attribute / droptable / set / modifier）。

触发：读写 `content/` 数据、新增内容对象或类型、构造内容夹具（尤其「小词缀池」类）、改动掉落/词缀过滤字段前。

## 过滤字段缺省 = 匹配一切

- `allowed_slots` / `allowed_categories` **不写即不限**，不是「不匹配」。
- 推论：靠「换基底槽位 / 换类别」造不出小词缀池——只要池里存在无过滤字段的通用词缀，它永远命中。
- 正确做法：把无过滤的通用对象**整体挪到别的槽位 / 文件**（如 `_loot_affix_files(["weapon"])` 场景下把 6 条无过滤通用词缀挪走），才能造出「池 < 档位词缀数」的情形。

## 构造夹具的三条规则

1. 先分清要验证的是**结构**还是**数值**：结构类断言走免概率通道（如首领掉落率 `p = 1.0`），不要靠随机采样碰。
2. 采样类断言按余量给样本量（分布断言 N=120 时余量偏薄，N=240 后舒适）——详见 `godot-standards.md`「断言质量」。
3. 数值类夹具不要拿真实内容当必胜假设：真实平衡下裸装 1 级玩家打 5 只 8AP 骷髅武士必输（40 伤害/拍 vs 100HP）。引擎断言用 mini fixture（弱怪 + 一击必杀），**内容平衡不属引擎票**。

## 从载荷重推导时先分流乘算来源

传奇词缀的 `stat_amp` 等乘算来源不在 `values` 里（`values` 恒空）、两阶段聚合又是「先加算后乘算」。从载荷累加推导期望值时漏掉乘算来源，会把正确实现误判成 bug（实测：期望 11 / 实测 14）。

## 边界

- 本页只记**会改变数据写法 / 夹具构造**的语义。加载期轻量断言以 `game/src/content/content_db.gd` 为真相；**入库门槛**（schema + 引用闭合 + id 规则）以校验器为唯一真相——`tools/validator/README.md`（CLI / pre-commit / CI 三处同源，#26 起）。
- **形状契约**（类型与字段）在 `schema/README.md` —— 新增内容对象或类型前先读：类型封闭集（九种）、`id` 即文件名、引用闭合、schema 内禁止写公式。
- 存档侧约定暂无落点（原存档约定页随 2026-09-05 回滚删除，待存档票 #38 一并重建）。
