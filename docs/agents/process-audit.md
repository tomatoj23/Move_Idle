# 流程自审（开发内）

执法体系本身也要被验证，不能靠假设运行。本页只收**正常开发过程中会撞上**的自审动作——发现问题 → 归类 → 当场反哺；需要造题库 / 翻会话导出 / 比对官方源 / 定期抽检的带外审计，见 `docs/agents/audit-runbooks.md`。

## 开发内触发时机

1. **写代码 / 评审 / 落稿时撞到标准页没覆盖或写错的点**（事实措辞不准、查文档走弯路、指针没生效、用了合法但次优的写法、设计文档用了已变更 API 提法）→ 当场裁决（ClassDB 实测 / 锁定版 class reference）→ 按下方映射表归类反哺。
2. **新资产类型首次落库**：首个 `.tscn` / `.tres` / `.gdshader` / `addons/` 落库前 → headless 实测引擎对该类型的行为（旧属性漂移的警告形态、shader 编译路径、插件兼容声明）→ 决定是否升级 lint / CI（如把可疑 warning 升为失败）。
3. **CI 红 / 编译错 / 钩子拦下** → 直接当数据点按「机器层漏网」归类处理；不跑探针，不启动带外审计。
4. **文档重排 / 回滚 / 删除文件后** → grep 全仓引用该文件的锚点（带条号的硬引用最易腐）。已机器化：`sh tools/check-doc-links.sh`（pre-commit 与 CI 同源，双平台验证）。

## 失守归类 → 反哺映射

| 失守类别 | 反哺动作 |
| --- | --- |
| 知识错误（事实/措辞不准，如 area_mask 归属） | ClassDB 实测裁决 → 修镜像（实测注记）/ 标准页 → 记日志 |
| 查证入口盲区（找文档走弯路） | 补标准页"查证入口" |
| 指针失灵（没走流程） | 加重指针措辞 / 标准页补判例 / 降遵循成本 |
| 机器层漏网（编译过但错） | 扩 lint 模式 / 加 CI 步骤 / 强化钩子 |
| 语义判断错（用了合法但次优的写法） | 标准页补判例；案例积累后上运行时测试（GUT/gdUnit4） |
| 规划类失守（设计文档用了已变更 API 提法 / 遗漏命中需求的新特性） | 扩触发面措辞 / 标准页补落稿 checklist 判例（探针侧补规划类题属带外，见 audit-runbooks） |
| **元层失守**（关于机制 / 文档自身的教训） | 反哺落点 = `AGENTS.md` / 本页 / `godot-standards.md`；**不得只留在 `.codebuddy/memory/`**（被 gitignore = 不可评审、换机即失）。放进下方「三个层级」判断该落哪一层 |

## 机制可靠性的三个层级

同一条规则放哪一层，决定它到底会不会被执行：

1. **机器层（CI / pre-commit）** —— 强制，不依赖会话自觉。**能被静态匹配的规则一律下沉到这里。**
2. **skill 层** —— 由 description 触发、按需注入。适合「需要判断但会重复发生」的动作；它不依赖「我要去找规范」这个意图，而这正是指针层的失效点。
3. **文档指针层** —— 最弱，依赖会话主动回读。只在上面两层都不适用时使用。

判断顺序：能静态匹配 → 机器层；需判断且会重复 → skill；其余 → 文档。
**只落在第 3 层的教训会跨会话重复踩**（审计 2026-09-06：四条复发实例，如「GDScript 缺键访问是运行时错误」记下后次日再次发生、静默吞掉 11 条断言）。

新增检查时必须验证它在**新克隆**上真的生效——`.github/workflows/docs.yml` 的 windows-latest job 做的就是这个：行尾被改成 CRLF（`#!/bin/sh` 解释器行失效）、hooksPath 未装机、PATH 里没有 sh，这三类问题在 Linux CI 上永远查不出来，表现为「本机静默失败、CI 全绿」。

## 反过度工程边界

- CI 红、编译错本身就是日常数据点，无需为此跑探针；
- 体系未变时不把带外审计跑成仪式；
- 机制的成本上限 = 本页 + `audit-runbooks.md` + 用户手里的题库；使用频率证明需要时，再包一层 skill（内容即这两页，skill 只是触发器）。
