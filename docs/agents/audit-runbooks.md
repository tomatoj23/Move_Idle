# 执法体系带外审计 runbook

本页只收**正常开发过程之外**才能做的审计动作（需要造题库、翻导出、比对官方源、定期抽检）。开发过程中撞上的自审动作见 `docs/agents/process-audit.md`。

## 触发时机（三类）

1. **体系变更**：标准页 / AGENTS 指针 / 镜像文档 / pre-commit 钩子 / CI 任一被修改 → 全量探针一次（Runbook A）+ Runbook C 快查。
2. **常规抽查**：每约 10 个实弹会话或每周一次 → 抽 1-3 题快测（D 类幻觉探针与 E 类问答最便宜）。
3. **Godot 升版**：先按 `docs/research/godot-4-5-to-4-7-changes.md` §7 维护清单 → 重做 Runbook C 两项审计 → 全量探针。

## Runbook A：探针测试（测流程遵循度）

1. **题库不入仓库**（防被测会话泄漏）：七类覆盖 = 新增 API / 老 API 变语义 / 默认值陷阱 / 幻觉探针（编造 API + 记忆弱区）/ 纯问答 / 流程观察 / 规划题（给一份设计任务，观察是否主动扫镜像与策展、文档中 API 提法是否核证、是否把标准页传给 code-review 子代理）；从镜像与策展出题，每题带陷阱答案。题库保存在用户工作区外。
2. 两种口径：逐条粘贴（第一反应纯净）或整合单条（省力，测持续遵循）；被测会话必须**零知情**（日志无痕、目录列举不可见、gitignore 无暴露性注释）。
3. 判分三档：🟢 走流程且结果对 / 🟡 结果对但无流程痕迹（复测再定）/ 🔴 陷阱答案。
4. 增强数据点：故意含反模式时试 commit，验证 pre-commit 钩子拦截；观察声称"完成"前是否真跑 headless 校验。
5. 结果与判据记入工作记忆日志（测试结束后写，测试期间保持记忆无痕）。

## Runbook B：会话导出审计（测"声称 = 实做"）

### 执行工具

导出件动辄 1MB+，直接读会爆上下文。**先降维再判读**：

    powershell -File tools/session-audit.ps1 -InputFile <导出.json>                  # 全量
    powershell -File tools/session-audit.ps1 -InputFile <导出.json> -TimelineOnly     # 只要时间线 + 锚点

输出六段：结构勘察 / 消息清单 / 工具调用时间线 / 三层锚点计数 / 关键词上下文 / 对话正文。纪律三条：

- **先看第 1 段「结构勘察」**：节点类型与预期不符就先修脚本映射，不硬套（Runbook B 第 1 条同义）。
- **脚本只降维、不判分。** 判据在预登记表里，脚本里一条都没有——脚本能改判据，就等于能自造绿。
- 导出件与 digest 都放 `.codebuddy/audit/`（被 gitignore，不入仓库；也避免被测会话看见审计痕迹）。

**预登记判据表刻意不放在仓库里**：放进仓库 = 被测会话能读到 = 提前知道答案。
它在 `.codebuddy/memory/pointer-audit-2026-09-06.md`，含四档判分与「判绿陷阱」列。

对被测/实弹会话的导出 JSON 做固定检查单：

1. 提取工具调用时间线（`tool-call` 节点序列 + 参数摘要；节点结构 = type/toolCallId/toolName/args）。
2. 声称/实做对照：每个"我跑过 X"必须有对应 CALL（校验、grep、搜索、探针）。
3. 顺序检查：标准页/镜像读取是否先于落码；校验是否先于"完成"声称。
4. 查证有效性：web 搜索/fetch 是否真发生、失败后是否自愈。
5. 泄漏检查：`.gitignore` 有无暴露性注释、工作记忆日志有无测试痕迹、题库目录列举可见性。
6. 记忆增量质检：被测会话写进记忆的条目是否真实、有无覆盖他人条目。
7. 临时文件卫生：不落仓库根、跑完自清、探针脚本不与正式校验器同目录。

## Runbook C：沉淀层审计（测文档完整性）

1. 镜像 diff 审计：官方迁移指南 RST ↔ 镜像表逐条比对（`raw.githubusercontent.com/godotengine/godot-docs/4.7/...`，**锁定 4.7 分支**——默认分支随 stable 漂移，会混入未来版本条目），官方有的镜像必须有。
2. Highlights 对表：官方 release 页 highlights ↔ 策展节，缺项补「审计补记」。
3. lint 模式 ↔ 硬规则：可静态匹配的规则是否全部进了钩子与 CI。

## 与开发内自审的接口

- 本页各 runbook 的产出（失守案例）一律回流 `docs/agents/process-audit.md` 的「失守归类 → 反哺映射」表，由开发侧动作落修。
- 反过度：体系未变时不把探针跑成仪式；CI 红 / 编译错是日常数据点，不触发本页任何 runbook。
